# Database and backup

Home labs and this prototype stay on SQLite (`data/koreograf.db`, WAL, one writer). An empty `KOREOGRAF_DATABASE_URL`, or a value of `sqlite:`, means that file. A `postgres://` URL stops startup with a clear message until a company database exists. The backup from the UI is the hand-off format for that later move: one SQLite file plus the key, not a raw copy of the data directory.

An administrator opens **Backup** in the sidebar. In the German UI the link is **Sicherung**.

- **Download** writes `koreograf-backup.zip`. Inside are `manifest.json`, a consistent database (`koreograf.db`, copied through the SQLite backup API), and `secret.key`. Without the key, credentials cannot be read after a restore. The manifest keeps a versioned `format`, the engine, the creating version, and `includes`/`omits` lists.
- **Include OpenTofu state** is off by default. When it is on, the zip also contains `cache/<team>/tofu-state/<template>/`. That state can contain secrets such as provider values or resource attributes. A remote backend is still the better setup when state must leave the host.
- **Left out** are the other parts of the cache, git checkouts, and job directories. The next run fetches collections and roles again, and git projects are cloned again. A template that does not update on launch needs a project sync after a restore. Projects that use a local path need that same path, or a matching `KOREOGRAF_PROJECT_ROOTS` entry, on the target machine.
- **Restore** replaces the installation. Finish running jobs first. The request sends the zip body and the header `X-Restore-Confirm: ERSETZEN`. A new sign-in is required afterwards. The previous installation stays as `restore-previous.zip` in the data directory (mode `0600`) and can be restored the same way. An unknown manifest `format` is refused before anything is replaced. Restore replaces the OpenTofu state directories under `cache/<team>/tofu-state/`; state that is not in the backup does not survive.
- **Restore on start** uses `KOREOGRAF_RESTORE_FROM=/restore/koreograf-backup.zip` when the data directory is empty. It restores before the port opens, logs the result, and renames the file to `koreograf-backup.zip.applied` so a restart does not apply it twice; mount that directory writable. A non-empty data directory ignores the variable with a warning and overwrites nothing. The API keeps the confirm header.
- **Import an existing data directory** uses `KOREOGRAF_IMPORT_FROM=/import` on the first start with an empty data directory. Koreograf validates `koreograf.db` and `secret.key`, copies the database with the SQLite backup API so an active WAL file stays consistent, copies the key and the OpenTofu state, and writes a report. A cleanly stopped installation without a WAL file is read through a read-only immutable URI, so both a running and a stopped old service work. The import writes into a hidden staging directory and moves it into place only after the database, key, state, and report are complete; a failed run leaves the data directory empty and the next start retries. `KOREOGRAF_IMPORT_CACHE=1` also copies the rest of the cache. The source directory is only read; nothing is written to it. A non-empty data directory ignores the variable.
- The import refuses a database with a schema newer than this build. Older databases are migrated when they can be read.
- Stored path-project sources and `KOREOGRAF_PROJECT_ROOTS` that do not exist in the container are listed in the log and on the Overview page as paths that need a mount or a change. `KOREOGRAF_PATH_MAP=/home/user/projects=/projects` rewrites matching path-project sources once during the import and stores the mapping in the database. There is no guessing; a path that is not in the map stays unchanged.
- Files written into the data directory belong to uid 10001 when the container starts as root through the entrypoint. In the published image the server itself already runs as uid 10001.
- The file is secret: it contains users, hooks, and the key for every credential. The upload and total backup limit is 256 MiB; a download that would exceed it fails instead of producing a backup that restore refuses.

`GET /api/admin/backup` and `POST /api/admin/backup` are limited to the local administrator. `GET /api/admin/backup?tofu_state=true` includes the OpenTofu state. The migration steps with commands are in [Installation](installation.md#move-from-a-binary-or-systemd-install).
