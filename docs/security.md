# Security

The prototype is meant for a trusted network. The Docker socket is root on the host. A mounted `/var/run/docker.sock` lets Koreograf start an image an owner or an operator selected, with mounts and a command that image chose. Anyone who can reach the socket can also start a privileged container and read or change the host. Prefer rootless Podman or rootless Docker, which still limit the host but map the socket to a user. The next step is a socket proxy that allows only the calls Koreograf makes: `version`, `info --format`, `image inspect`, `pull`, `run`, `inspect`, `kill --signal`, and `rm -f`. A proxy still sees those calls as permission to start arbitrary images, so it is not a sandbox. Do not expose the socket over TCP without TLS and authentication. The published image runs as uid 10001. It joins the socket's group only when the container runtime or chart start it with that group. The job container does not receive the socket. It does see the decrypted credential files of that job. The Helm chart keeps uid 10001 with the socket's gid in `supplementalGroups`. `data/secret.key` decrypts every credential and the saved directory and proxy passwords. Copying that file, the SQLite database, or `koreograf-backup.zip` exposes them. `KOREOGRAF_LDAP_TLS_INSECURE` and an open port without TLS do not belong on the internet. `KOREOGRAF_LDAP_CA_FILE` and a NetBox source `ca_file` are absolute PEM paths. When one of them is set, certificate checks stay on. Turning checks off writes a warning, and a NetBox source that does so shows a badge. Responses set `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, and a content security policy. Pages set layout with style attributes, so that policy allows those attributes and still blocks inline scripts. `KOREOGRAF_HSTS=true` adds `Strict-Transport-Security`. Leave it off when the process is reached over plain HTTP. `KOREOGRAF_COOKIE_SECURE` defaults to `auto` and does not mark the session cookie `Secure` until a trusted proxy reports HTTPS, or until the flag is `true`.

Local jobs run as the server user. The container image has no local mode and no local tools. Outside the image, `KOREOGRAF_LOCAL_RUNNER_FOR` defaults to `admins`, so an operator or an anonymous webhook cannot start one. The template, project, inventory, and workflow that supply the command must have been saved by an administrator. Relaunch checks the stored parameters, not only the template as it looks now. The job process does not inherit the server environment. Ansible extra vars are written as unsafe YAML, so a webhook value is not evaluated as a template. Decrypted credential files are removed when the job ends and again on the next start. A container cannot mount the data directory.

Path projects and `file://` clones cannot use the data directory or a system directory such as `/etc`. The examples directory is always an allowed root. Any other directory has to be listed in `KOREOGRAF_PROJECT_ROOTS`, and a saved path outside those roots does not run. See [Configuration](configuration.md).

LDAP sign-in does not take over a local account that already uses the same username. A team bound to a group DN matches that directory entry. A CN binding matches the CN under the search base.

If an operator who should not have been trusted could start local jobs, create new credentials and retire the old ones, `secret.key` decrypts every stored secret, and a backup zip from that period contains the same key.

How to report a vulnerability is in [SECURITY.md](../SECURITY.md).
